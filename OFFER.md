# Proposed workflow-repair packages

**Proposed service by x0Lazarus.** These prices are draft offers, not paid engagements or an earnings forecast. The included demonstration uses only synthetic data.

## $150 — repair one small import

For one existing local Python CSV/JSON workflow with a confirmed defect and an agreed input/output schema:

- One defect reproduced with a small synthetic or customer-approved sample.
- A focused repair, useful validation errors, and regression tests.
- A runnable handoff with setup and usage instructions.
- One revision round against the written acceptance criteria.

The work must fit a small repair: one script, one input format, one output format, and no external-system integration. If discovery shows a larger problem, agree a new scope before implementation. The price is not an unlimited debugging commitment.

## $300 — harden one recurring export workflow

For a single local data-cleaning/export workflow with a written schema and up to two agreed input variants:

- Reproduce and repair the agreed parsing/transformation problem.
- Add strict validation and deterministic output, with safe file replacement where applicable.
- Add representative valid/invalid fixtures and tests of failure behavior.
- Supply a CLI, usage guide, and a short before/after evidence note.
- One revision round and seven calendar days for corrections to defects against the agreed acceptance criteria, starting at delivery.

New requirements, changed source formats, extra integrations, data recovery, ongoing operations, hosting, and support after that correction window require a separate agreement. No promise of upstream OSS acceptance or an upstream merge is included.

## Start and acceptance

Before work starts, agree the deliverable, anonymized/synthetic sample, input schema, expected output, validation cases, deadline, permitted tools, data-handling restrictions, ownership/license, payment terms, and who accepts the result. Use a funded milestone or another mutually agreed payment arrangement. Do not send credentials or sensitive production records for initial scoping.

Acceptance is based on the written examples and tests, not subjective statements such as “handles every CSV.” The supplier remains responsible for the deliverable and customer communication. Use only data the customer has authorized for the agreed tools and environment.

The customer runs the delivery in a nonproduction environment before adoption. Deployment, write access to customer systems, and unattended operation are separate scope decisions. Platform charges, tax obligations, acquisition time, and revisions reduce the supplier's actual profit; a $300 invoice is not $300 profit.
